# Лабораторна робота №1 — TypeScript

Проста шпаргалка для захисту: що робить кожен файл + готові відповіді на контрольні запитання.

## Як запустити проєкт (Завдання 1)

1. Встановити [Node.js](https://nodejs.org/en) (якщо ще немає).
2. У папці проєкту: `npm init -y` → створює `package.json`.
3. Встановити TypeScript: `npm install --save-dev typescript` (локально) і, за бажанням,
   `npm install -g typescript` (глобально, щоб команда `tsc` була доступна будь-де).
4. Ініціалізувати TS: `npx tsc --init` → створює `tsconfig.json`.
5. Налаштувати компілятор (уже зроблено у файлі `tsconfig.json`): вихідна папка `dist`,
   папка з вихідним кодом `src`, режим `strict` для суворої типізації.
6. Компіляція всього проєкту: `npm run build` (виконує `tsc`), запуск конкретного файлу:
   `node dist/task4_animals.js`.

Для Завдання 3 додатково потрібен пакет для `prompt`:
`npm install prompt-sync @types/prompt-sync`.

## Що робить кожен файл (для захисту своїми словами)

- **task2_variables.ts** — оголошує змінні типів `string`, `number`, `boolean`, `any`,
  масиви `string[]` і `number[]`. Показує, що TypeScript сам перевіряє, чи ви не поклали
  в масив чисел рядок і навпаки.
- **task2_functions.ts** — функція з **параметром за замовчуванням** (`age: number = 18`).
  Якщо виклик не передає вік — підставляється 18.
- **task3_icecream.ts** — рахує ціну морозива: базова ціна розміру + сума начинок +
  маршмелоу, якщо обрано. Дані вводяться через `prompt` (пакет `prompt-sync`, бо в
  Node.js немає вбудованого `prompt()`, як у браузері). Використано **union-типи**
  (`"маленький" | "великий"`), щоб дозволити лише конкретні рядки.
- **task4_animals.ts** — інтерфейс `Animal` описує, що вміє тварина (властивості + метод
  `move()`). Властивість `legs` зроблена **опціональною** (`legs?`), бо рибі "ноги" не
  потрібні. Класи `Cat`, `Bird`, `Fish` реалізують (`implements`) цей інтерфейс.
- **task5_shapes.ts** — інтерфейс `Shape` з методами `getArea()`/`getPerimeter()`. Класи
  `Circle`, `Rectangle`, `Triangle` рахують площу/периметр кожен за своєю формулою і
  вміють масштабуватись (`scale(factor)`). У масиві `Shape[]` лежать різні фігури разом —
  це і є сенс інтерфейсу: код працює з будь-якою фігурою однаково.
- **task6_cars.ts** — абстрактний клас `Car` (не можна створити "просто машину", лише
  конкретну марку). Показано всі три модифікатори доступу: `private` (тільки всередині
  класу, напр. VIN), `protected` (клас + нащадки, напр. `brand`), `public` (доступно
  всюди, напр. `model`). Нащадки `Toyota`, `BMW`, `Audi` викликають `super()`, щоб
  передати дані в конструктор батька.
- **task7_employees.ts** — абстрактний клас `Employee` з абстрактним методом
  `getAnnualBonus()` — кожен нащадок сам вирішує, як рахувати бонус (`Developer` — 10%,
  `Manager` — 20%). Інтерфейс `Payable` з методом `pay()` реалізують обидва класи.
- **task8_courses.ts** — інтерфейс `Course`, клас `OnlineCourse` реєструє студентів і
  перевіряє, чи студент вже є в списку. `CourseManager` керує масивом курсів:
  додає/видаляє/шукає за назвою (`find` повертає `Course | undefined`, бо курс може
  не знайтись).
- **task9_library.ts** — інтерфейс `LibraryItem` (назва, автор, метод `borrow()`).
  Класи `Book`, `Magazine`, `DVD` додають свої унікальні поля (сторінки, номер випуску,
  тривалість). Клас `Library` зберігає всі елементи разом і вміє шукати за назвою.

## Відповіді на контрольні запитання

1. **Що таке TypeScript і переваги над JS?** — Надбудова над JavaScript, що додає
   статичну типізацію. Переваги: помилки типів видно ще до запуску коду, зручніша
   автодоповнення в редакторі, легше підтримувати великий проєкт.
2. **Як налаштувати середовище?** — Встановити Node.js → `npm init` → встановити
   TypeScript → `tsc --init` для `tsconfig.json` → писати код у `.ts` → компілювати `tsc`.
3. **Що таке tsconfig.json?** — Файл конфігурації компілятора: куди класти результат
   (`outDir`), яку версію JS генерувати (`target`), чи вмикати сувору перевірку
   (`strict`) тощо.
4. **Основні типи даних** — `string` (текст), `number` (усі числа), `boolean`
   (true/false), `any` (будь-який тип, перевірка вимкнена), також `void`, `null`,
   `undefined`, масиви, кортежі, `enum`.
5. **let vs var** — `let` має блокову область видимості (`{}`) і не дозволяє повторне
   оголошення; `var` — функціональну область видимості, застарілий, поводиться менш
   передбачувано.
6. **Тип any** — вимикає перевірку типів для змінної. Використовувати тільки коли тип
   справді невідомий заздалегідь (наприклад, дані ззовні), бо він "ламає" переваги TS.
7. **Власний тип** — через `type` або `interface`:
   `type Point = { x: number; y: number };`
8. **Компіляція в JS** — командою `tsc файл.ts` або `tsc` (компілює весь проєкт за
   `tsconfig.json`), результат — `.js` файл.
9. **Режим --watch** — `tsc --watch` перекомпільовує файл автоматично щоразу, коли ви
   його зберігаєте, зручно під час розробки.
10. **Опції tsconfig.json** — наприклад: `target` (версія JS на виході), `outDir` (папка
    результату), `strict` (сувора типізація), `rootDir`, `module`, `sourceMap`.
11. **Навіщо map-файли** — `.js.map` зв'язують скомпільований JS з вихідним TS, щоб при
    налагодженні (debug) у браузері/IDE можна було бачити оригінальний TS-код, а не
    згенерований JS.
12. **Оголошення типізованої змінної** — `let count: number = 5;`
13. **Типи масивів** — `string[]` або `Array<string>` — масив, де всі елементи одного
    типу; TS не дасть покласти туди елемент іншого типу.
14. **number vs any** — `number` дозволяє класти лише числа (помилка при спробі
    покласти рядок), `any` дозволяє все, перевірка типів повністю вимкнена.
15. **Функція з типами** —
    `function sum(a: number, b: number): number { return a + b; }`
16. **Параметри за замовчуванням** — значення, яке підставляється, якщо аргумент не
    передали: `function f(x: number = 10) {}`.
17. **Функція void** — функція, яка нічого не повертає (не має `return значення`);
    використовується, коли важлива лише дія (наприклад, `console.log` всередині), а не
    результат.
18. **call, apply** — методи функцій у JS/TS, що дозволяють викликати функцію з явно
    заданим `this` та аргументами (`call` — аргументи через кому, `apply` — масивом).
19. **Наслідування в TS** — через ключове слово `extends`: клас-нащадок отримує всі
    поля/методи батька і може викликати `super()` для виклику конструктора батька.
20. **Абстрактний клас/метод** — абстрактний клас (`abstract class`) не можна створити
    напряму (`new`), він лише база для нащадків. Абстрактний метод (`abstract method()`)
    не має реалізації в базовому класі — кожен нащадок зобов'язаний її написати.
21. **implements** — показує, що клас зобов'язується реалізувати всі поля/методи,
    описані в інтерфейсі. Компілятор перевірить це і видасть помилку, якщо щось
    пропущено.
22. **private vs protected** — `private`: доступ лише всередині самого класу; 
    `protected`: доступ у самому класі і в усіх його нащадках (але не ззовні).
23. **static, readonly** — `static`: властивість/метод належить самому класу, а не
    конкретному об'єкту (`Клас.метод()`); `readonly`: значення можна встановити один раз
    (зазвичай у конструкторі) і далі змінити не можна.
24. **Опціональні параметри в інтерфейсі** — властивість, позначена `?`
    (`age?: number`), не є обов'язковою — об'єкт може її не мати.
25. **Навіщо конструктор** — спеціальний метод класу, що виконується автоматично при
    створенні об'єкта (`new Клас(...)`) і використовується для ініціалізації полів
    початковими значеннями.
